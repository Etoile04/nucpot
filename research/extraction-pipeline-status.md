## Q1. BUG-25 三条抽取路径的收敛状态(代码级)

### 命名澄清(易混)

- `services/extraction_orchestrator.py` 的 `ExtractionOrchestrator`(965 行)= 本报告的 **路径 B**("V2 pipeline shell, NFM-2568-T1"——文件自称 V2,但相对 v4 API 它是第一代 orchestrator,即 #1250 语境的 "v1 ExtractionOrchestrator")。
- `services/extraction_orchestrator_v2.py` 的 `ExtractionOrchestratorV2`(147 行)= **路径 C**(#1250 语境的 "v4 ExtractionOrchestratorV2",strangler-fig NFM-2677 B7)。
- `services/extraction_pipeline.py` 的 `ontofuel_extract`(LLM 直调函数)= **路径 A** 的核心。

### 路径 A:literature_service → ontofuel_extract(生产主力,未变)

调用链(全部在 origin/main 上核实):

```
POST /api/v1/extraction/... (api/v1/extraction.py:56 trigger_extraction_job)
  → task_dispatcher.dispatch(process_literature_task)   # Celery,C4 seam(73314f5db,2026-09-07)
  → literature_dispatcher.process_literature_task (literature_dispatcher.py:270)
  → literature_service.process_literature (literature_service.py:406)
      PDF→Markdown(PyMuPDF)→ ontofuel_extract(source_type='datasource')  # literature_service.py:569
      → extraction_to_db_mapper.map_and_persist → kg_re.GraphBuilder
```

要点:

- `ontofuel_extract`(`extraction_pipeline.py:418`)是 OpenAI 兼容 LLM 调用 + 分块合并(NFM-1366 P3),支持 `llm_call` 注入(ADR C2/NFM-2564)。
- **本体驱动 prompt 已强制**:`extraction_pipeline.py:531-536` —— 无已发布 OntologyVersion 直接 `raise ValueError`,有则 `build_ontology_extraction_prompt(ontology_version)`(NFM-3258;prompt 生成自本体 entity_types/property_categories,非硬编码,NFM-3004)。召回上限=本体目录内容,这是 Q3/Q4 与 Q1 的交叉点。
- ingest 侧(NFM-2564 C3,`services/ingest_service.py`,ebd171e67,2026-09-07)同样汇入 `process_literature_task`。**C3/C4 是 seam 重构,不是三路收敛**。

### 路径 B:v1 ExtractionOrchestrator(仍有两个活性入口)

`extraction_pipeline.trigger_extraction()`(`extraction_pipeline.py:734`)构造并运行 B(806 行处),**但该函数在 src/ 内已无生产调用方**(全仓 grep 仅测试与注释引用)。B 的活性入口只剩:

1. **单步重跑**:`POST /api/v1/jobs/{job_id}/steps/{step_name}/rerun`(`api/v1/jobs.py:33` → `trigger_step_rerun` → `extraction_pipeline.py:1117 orchestrator.rerun_step`;幂等键 NFM-3599)。
2. **本体升级重抽取队列**:`api/v1/re_extraction.py:341` → `re_extraction_worker.process_single_entry` → `ExtractionOrchestrator(...).run()`(`re_extraction_worker.py:276`)。

B 内部 5 步(chunk/extract/map/quality_gate/gap_scan,`extraction_orchestrator.py:37-43`),其 extract 步逐 chunk 经临时文件**回调路径 A 的 `ontofuel_extract`**(`extraction_orchestrator.py:649-660`)——即 B 不是独立第三套 LLM 逻辑,而是 A 的编排包装。

### 路径 C:v4 ExtractionOrchestratorV2(仅 v4 submit 触达;extract 步是正则 stub)

```
POST /api/v4/extraction/submit (api/v4/extraction.py:239,Depends(require_editor))
  → trigger_extraction_pipeline (extraction_pipeline_dispatch.py:252)
  → _run_v2_pipeline → ExtractionOrchestratorV2.run
      RawTextLoader → SectionSegmenter → EntityExtractor → PropertyNormalizer → ChunkBuilder
```

- 派发层状态:`extraction_pipeline_dispatch.py:1-6` 明言 "Single external entry point that routes to the V2 orchestrator. The legacy V1 path and `extraction_v2_enabled` flag were removed in NFM-3008 (Phase B final cutover)"——**flag 时代的双路分发已死**,`trigger_extraction_pipeline` 现在 100% 走 C。
- content 契约(ADR-NFM-2737 §D5):`load_v2_content` 支持 file/internal_id/空串(file-path 语义)与 doi(stub 模式回退占位符);**`url`/`datasource` 显式 `NotImplementedError`**(`extraction_pipeline_dispatch.py:238-243`)——即生产主流的 datasource 摄取**不可能**走到 C。
- **EntityExtractor 仍是正则 stub**(`services/extraction/steps/entity_extractor.py`):化学式正则 `_FORMULA_RE` + 14 个硬编码属性名 `_PROPERTY_NAMES` + 数值-单位正则 `_MEASUREMENT_RE`。PropertyNormalizer/ChunkBuilder 同样是确定性字符串处理——**五步全链无 LLM**。此 stub 是 v0.4 目录之外的第二个召回天花板(若哪天生产流量真走 C)。

### 收敛判定

- **三路并存仍在**(A 生产主力 / B 两个窄入口 / C v4 API 专属),截至 2026-09-08 无收敛提交(`git log --grep` BUG-25/NFM-2564/converge:最近的 NFM-2564 C2/C3/C4(09-07)是 VLM 端口化、ingest 下沉、task-dispatcher seam,不动三路拓扑)。
- 已完成的是**分发层的去 flag 化**(NFM-3008,032398e91,2026-08-15):`extraction_v2_enabled`/dataclass `ExtractionJob`/`_job_store` 已删(ADR-NFM-2739 → Implemented,NFM-3009)。
- ADR-NFM-2737(`docs/architecture/ADR-NFM-2737-strangler-fig-extraction-dispatch.md`)仍是现行决策文档;它规定的 D4 长期方向(削 dataclass)已做,但"V2 完整接管 datasource/url"的前置(§D5)未动工。
- 对 #1252(召回路线)的直接含义:**路线选择不受"已收敛"假设支撑**——任何"以管线 X 为基础"的方案都要先回答落在 A/B/C 哪一路,而 C 当前不具备生产摄取能力(datasource NotImplementedError + 正则 stub)。
