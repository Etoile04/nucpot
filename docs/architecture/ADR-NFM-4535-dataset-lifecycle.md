# ADR-NFM-4535: 数据集生命周期——每文献隔离、校核门、快照版本、双回退

**Status:** Accepted(2026-09-10,wayfinder #1280 决议,owner 四项亲答;坍缩入库随 #1257)
**Date:** 2026-09-10
**决策记录:** GitHub issue #1280(由 #1253 取证与 owner 深层追问驱动)
**实证先例:** ①摄取判重失败事故(同文 8+ 次摄取,0.3 eV ×13 行跨 10 dataset,标题退化 UUID);②09-02 迁移事故(41 行 attribution=lost,ADR-011/012)——「单次意外毁掉数据集」的两次真实发生;③今日"回退"= 人工 SQL(NFM-4394/4395 先例),无审计无版本

---

## 1. Context

owner 框定:提取数据集应按每篇文献单独提取并校核后再合并;合并的数据集需版本管理,允许回退,避免单次意外错误毁掉整个数据集(例如摄取判重失败时,可回退/删除某篇文章引入的数据)。解法不仅是前端界面,要从数据管理层面设计。

现状:datasets 表按 source_id 有行级隔离但语义松散(同文多源、无判重);无版本列;合并 = NFM-4312 式手工 backfill(无版本痕迹);消费方直读最新数据。

**备选方案**:①仅加判重不动模型(身份语义仍弱);②快照式版本表 + 双回退;③增量日志式(回退 = 反向重放,复杂易错)。

## 2. Decision

**采用②:快照式生命周期模型**,四项决策(owner 亲答,#1280):

1. **隔离与身份**:每文献一个私有数据集;身份判重 DOI 优先、内容哈希兜底;同文献重抽产生该数据集**新版本**而非新数据集——「同文多源」结构性不可能
2. **校核门**:行级五动作校对(确认/需修改/标记无效/来源存疑/跳过)+ 物理有效域通过 → 行进入可合并集;低置信度行必须人工通过;**版本 = 可合并集快照**
3. **版本与回退**:快照式 `dataset_versions`(版本号/材料/行集引用/来源清单/时间);**双回退**——整版本回退 + 按源剔除(移除某文献贡献后再快照);回退 = 切版本指针
4. **消费方**:发布版(验证/物性页/检索/导出)与工作版(校对页)分离;**AutoVC 验证结果记录所用版本号**(等级可追溯)

## 3. Consequences

- **正向**:摄取事故的影响半径从「全库」缩到「一版本」;按源剔除让 owner 的「删某篇文章数据」用例成为一等操作(带审计,取代人工 SQL);验证等级可溯到数据版本;重抽试点有安全容器(不动存量)。
- **代价**:一次 schema 迁移(dataset_versions + conditions/composition 列);API 双读路径;快照存储成本(量级:当前百行级,可忽略;未来按行集引用而非复制行)。
- **对照先例**:本模型下 09-02 事故 = 回退一个版本,而非 41 行 attribution 永久丢失 + DataLossNotice 事后告知。
