## 1. 概述

本项目旨在建设核燃料材料数据平台，用于实现核燃料材料相关数据的统一存储、规范管理和综合应用。平台围绕材料数据资源的录入、治理、查询分析、知识关联和模型应用等需求，通过数据存储技术、知识图谱技术和机器学习技术的结合，构建一体化的智能数据管理与分析平台。

平台采用混合存储架构（关系型与非关系型数据库协同），支持多源异构数据的统一管理，并通过智能体提升数据抽取入库自动化水平，减少人工干预。平台核心功能包括数据录入与结构化、知识图谱构建、数据查询分析、机器学习建模等。提升核燃料材料科学全链条数据资源管理水平和利用效率，为后续材料研究、数据分析及相关应用提供技术支撑。

本技术规格书规定了"核级材料关系型数据库规范与开发"项目承担单位应完成的工作内容及工作的方式、进度、成果、技术指标等，作为合同执行的技术依据。

## 2. 工作目标

本项目旨在建设一个集数据混合存储、数据汇交、知识图谱、机器学习及综合管控**五大模块**于一体的核燃料材料数据平台。针对当前数据录入效率低、多源异构数据整合困难、分析依赖人工干预等痛点，通过以下具体目标实现平台建设。

### 2.1 典型应用场景

- **材料数据抽取**：从非结构化PDF文档中自动提取成分、性能等关键信息
- **知识图谱构建**：实现多源数据的消歧、融合与动态更新，并提供知识图谱应用服务
- **数据混合存储**：对核燃料材料数据提供统一存储、录入、权限、审核与分析能力，实现多类型数据的规范化管理
- **机器学习建模**：提供数据建模管理与应用能力，支持材料性能预测与反向优化方案生成

### 2.2 专项技术实施

- **智能体提取引擎**：通过大模型辅助材料数据信息抽取，实现PDF解析、多源搜索与结构化输出，减少人工录入工作量
- **流程自配置**：开发材料数据模板设计与校验工具，支持用户根据材料数据类型自定义数据录入模板，降低格式标准化门槛
- **跨模块协同**：构建数据混合存储系统与统一查询接口，实现数据"一次录入、多场景应用"

通过上述目标的实现，最终构建可部署、可扩展、可维护的核燃料数据平台，为未来新增业务场景（如实验数据自动归档、报告生成）和相关研究应用提供技术基础。

## 3. 工作内容和方式

### 3.1 工作内容

整个核燃料数据平台从功能角度可分为**5大部分**，分别是**数据混合存储模块、数据汇交模块、知识图谱模块、机器学习模块和综合管控模块**。各模块之间通过统一接口进行通信，系统部署支持中心节点与资源节点协同运行。

#### 3.1.1 数据混合存储模块

材料数据存在多源异构等特性，本数据库平台采用**关系型与非关系型数据库相结合的混合存储模式**，通过数据库适配机制集成 **MySQL、Elasticsearch、Neo4j** 等数据存储引擎，实现数据存储与一致性管理。

模块提供材料数据的**录入、编辑、查询、导入、导出、审核及可视化分析统计**等功能，开发**模板编辑器**以模板配置方式定义数据录入结构，同时系统支持**记录数据来源、批次及导入时间，实现数据来源追溯**，并支持**中心节点与资源节点之间的数据同步与汇交**。

#### 3.1.2 数据汇交模块

系统需支持**中心节点与资源节点**之间的数据同步与汇交机制。资源节点可进行本地数据录入、治理和存储，具备**数据包加密压缩、传输、解压导入**功能，并通过统一的数据汇交接口，将本地数据（包括新增、修改、删除操作）按预设策略（如定时、手动触发）同步至中心节点。

汇交过程需保证数据的一致性和完整性，支持**断点续传**，并记录**汇交日志**（包括汇交时间、数据量、状态等），以便进行数据追溯和审计。

> **数据入库强制要求**：数据在入库时，必须**自动或人工强制绑定数据 DNA 标识或密级标签**，实施数据多级分类及对应保护措施，涵盖平台内所有新增及存量数据。

#### 3.1.3 知识图谱模块

知识图谱模块用于对材料领域知识进行结构化组织和关联表达。支持对材料领域文档数据进行接入和解析，并结合大模型技术对**材料名称、化学成分、工艺参数、性能指标以及测试条件**等实体信息进行识别与提取，同时提取实体之间的关联关系。

需要对提取结果进行**人工校验和数据融合**，实现**实体统一、数据消歧及性能数据聚合**，并构建材料领域知识图谱，提供**实体关系查询、知识图谱可视化展示**，同时以**知识图谱查询接口**向外提供服务。

#### 3.1.4 机器学习模块

机器学习模块提供**模型的接入、训练、评价、应用和管理**等功能。提供模型上传入口，支持符合技术规范的外部模型接入运行，支持基于平台数据进行**训练建模和预测应用**，支持对特定数据集进行**正向预测和反向优化**、结果展示及可视化分析等功能以辅助材料领域研究。

#### 3.1.5 综合管控模块

综合管控模块用于对平台运行进行统一管理，并为系统运行提供安全和运维支撑。支持**用户管理、角色管理和权限管理**，实现不同用户角色的系统功能权限和数据访问权限控制，并具备**与甲方权限管控系统集成**的能力。

同时提供**组织管理、系统配置管理、日志审计、数据备份和服务器管理**等功能，以保障平台的稳定运行。

> **国产化要求**：具备**向国产化软硬件移植的能力**。

### 3.2 工作方式

本项目的实施过程中，乙方需结合甲方业务需求和部署环境开展前期准备工作，并根据平台建设内容完成系统开发、测试、部署和试运行支持等工作。

工具的研发部署分为两个环节：
1. 乙方先在**测试环境**进行工具的整体开发和功能测试，其中涉及文档解析、信息提取、自然语言查询等大模型辅助功能时，乙方负责相关功能开发、业务流程集成
2. 然后根据甲方的要求整体或拆解部分功能部署至**正式运行环境**，甲方需提供可调用的大模型接口及相关资源

乙方协助甲方及甲方联合承研单位进行功能部署，在系统试运行期间跟踪处理相关问题，并提供必要的培训和技术支持。

## 5. 技术指标

### 5.1 数据混合存储与数据管理能力

平台应采用混合存储架构，开发数据库适配器并集成 **MySQL、Elasticsearch、Neo4j**，实现平台数据的统一存储与一致性管理。

- 数据库可管理复杂异构关系型数据集，包括**成分、工艺、材料基础性能（热学、力学）、反应堆运行条件下肿胀、组分重分布、相结构**等关键服役性能等
- 支持的材料类型**不少于 10 种**（包括 **UO₂、UN、U-10Mo、U-10Zr、U-50Zr、UMoNbZr、不锈钢、镍基合金**等）

### 5.2 数据录入与校验能力

- 数据库应具有**可视化模板编辑器**，支持以**拖拉方式自定义设计数据模板**
- 支持 **Excel/CSV/JSON/XML** 等**不少于 4 种数据类型入库**
- **批量导入成功率达到 100%**
- 录入数据应有人工校验和审核接收流程，校验通过后方可入库

### 5.3 数据查询、分析与溯源能力

- 数据库应支持**基于关键词的数据检索**和**基于多重组合条件的高级检索**
- 至少支持 **2 类查询模式**（单一材料性能查询 + 多条件组合查询）
- 具备 **3 类以上数据分析展示方式**，包括但不限于表格、图、文本，并支持图表参数自定义及结果导出
- 具备对**数据来源、数据批次、导入时间**等信息进行查询与追溯

### 5.4 知识图谱构建能力

- 平台应支持包含 **PDF、Word、Excel、WPS** 在内**不少于 4 种常见格式**文档上传与解析
- 支持文档结构识别、表格与图像提取、文档元数据提取
- 应支持基于开源大模型的材料领域**实体识别和关系抽取**，并支持**人工校验、审核接收、数据消歧与融合、性能数据聚合**等功能
- 人工校验界面在加载单条复杂数据时，**页面响应时间 ≤ 3 秒**（以浏览器网络面板计时为准）

### 5.5 知识图谱查询与应用能力

- 提供知识图谱可视化展示、实体关系查询、自然语言查询以及**知识图谱查询 API 服务**
- 查询结果返回时间 **≤ 5 秒**（单次查询涉及不超过 **1000 个实体节点、10000 条关系边**的知识图谱规模下，且服务器配置不低于 **8 核 CPU、32GB 内存**）
- 知识图谱构建过程中形成的实体、关系及属性数据应支持**来源文档、提取时间、校准人员**等信息记录，实现图谱数据可追溯
- **随机抽查 10 条数据来源和操作记录完整度须达到 100%**
- 支持基于知识图谱抽取特定实体和关系并转换为特征数据，用于机器学习模型输入，支持**不少于 1 种导出文件格式**（如 CSV 或 JSON）

**核心量化指标**：
- 实体抽取准确率 **≥ 85%**
- 关系抽取准确率 **≥ 80%**
- 数据消歧准确率 **≥ 90%**
- （以人工校验结果为基准进行评估）

### 5.6 机器学习模型管理与应用能力

- 平台应具备机器学习模型管理与应用能力，支持**模型接入、训练、评价、迭代和应用管理**
- 满足材料数据建模**正向预测与反向优化**应用需求
- 支持模型结果展示、导出及可视化分析
- 平台应提供**至少 2 类模型评价指标**
- 允许符合平台技术规范的外部模型接入，并在接入过程中自动完成必要的规范性校验和运行适配处理
- 数据连接支持不限于 excel、csv 和 mysql 等类型数据的接入并进行管理

### 5.7 综合管控与运行保障

- 平台应具备统一的综合管控能力，为各业务模块提供基础运行与安全保障
- 系统应支持**权限、单位体系、服务等统一管理**
- 支持**至少创建 3 级组织架构**（如单位-部门-小组），且不同角色用户登录后看到的菜单权限严格不同
- 具备**安全审计、备份管理和系统运行管理**的安全防护能力
- 系统须**自动记录所有用户操作日志**，**日志留存时间 ≥ 6 个月**

### 5.8 多节点部署与协同运行

- 数据库平台采用 **1 个中心、5 个资源节点**部署架构，满足中心统一管理和资源节点协同应用需求
- 提供资源节点本地部署、本地数据建表存储，并支持**子节点数据灵活汇交**
- 可部署于甲方提供的服务器平台
- 具备支持**至少 30 人同时在线使用**的能力

### 5.9 系统部署与子节点离线功能完备性

**云端部署可用性**：
- 系统在云端部署后，可实现全功能访问，**全年服务可用性不低于 99.9%**

**子节点离线功能**：
- 子节点必须完整支持**数据录入、本地数据结构化存储、以及基于本地缓存的知识图谱查询**功能
- **核心离线操作的任务成功率达到 100%**

**数据同步**：
- 子节点在重新联网后，本地数据与云端同步的成功率及完整性**达到 100%**

### 5.10 多存储引擎协同工作性能

**查询响应时间**：
- 涉及跨引擎的复杂查询（如"查询某材料性能"），其**平均响应时间不超过 5 秒**

**系统稳定性**：
- 在压力测试下，多引擎协同工作**无故障、无数据丢失**

### 5.11 API 接口完备性

**接口完备性**：
- 核心功能预留的 API 或 MCP 接口，需提供完整的接口文档和测试用例
- **接口文档覆盖率达到 100%**
