## Methodology

1. Walk every `*.py` file under `apps/api/src/nfm_db/services/`, excluding `__pycache__`.
2. Map each file to its dotted module name relative to `apps/api/src/`. `__init__.py` files map to the package itself.
3. Parse each file with `ast.parse`; collect every `ast.Import` and `ast.ImportFrom`. Resolve each target to a module inside the services package by walking progressively shorter dotted prefixes until a known module is found. Both absolute imports (`from nfm_db.services.foo import Bar`) and relative imports (`from .foo import Bar`) are handled.
4. Build a directed graph where each `(consumer, producer)` pair contributes at most one edge, even if multiple names are imported from the same producer. Self-edges are dropped.
5. Fan-in = in-degree, fan-out = out-degree. Top-N tables list the top 5 neighbors by their own in-degree so the reader sees who the heavy hitters are coupled to.
6. Tarjan SCC identifies circular dependency chains; SCCs of size ≥ 2 are reported as cycles.
7. Cross-`providers/` edges are the subset where at least one endpoint is under `nfm_db.services.providers.` and the other is not, or both are in `providers/` but in different modules.
