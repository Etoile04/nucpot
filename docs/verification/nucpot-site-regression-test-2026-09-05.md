## 3. 新发现:#1141 修复引入的文件断链(建议追加为 BUG-37)

#1141 声称修复 BUG-06(势函数文件),实测文件覆盖确实提升(空文件从 19 条降至约 17 条,并新增了 Tersoff_Si 等带文件条目),**但新写入的 file_url 出现三种形态,其中两种是死链**:

| file_url 形态 | 示例条目 | 实测结果 |
| --- | --- | --- |
| `/uploads/<uuid>.tersoff`(相对路径) | Tersoff_Si_Tersoff_1989、Tersoff_SiC_Devanathan_1998 | **站点 404**;api/uploads、supabase uploads 等可发现的备选前缀均 404/400 —— 无任何服务路径 |
| `/app/uploads/Fe_Mendelev_2007v2.eam.fs` | EAM_Fe_Mendelev_2007v2 | **容器文件系统路径被当作 URL 存储**(必然 404),且向 API 消费方泄漏服务器内部路径 |
| `/storage/v1/object/public/potentials/...`(相对 Supabase 路径) | W-Ta_FS_2019 等大多数条目 | 依赖前端补全 Supabase 域名后可用(上轮 GUI 已验证);直连则 404 —— 可用但脆弱 |

**建议**:①为 `/uploads/` 增加静态服务路由(或入库前改写为可服务 URL);②清洗 `/app/uploads/` 形态数据;③统一 file_url 存储规范(绝对 URL 或后端代理路径),入 lint/迁移校验。

### 8.1 深层问题聚类

六项发现聚成四个结构性主题,均非孤立 bug:

1. **信息架构未对齐设计文档**(UAT-1):导航/页面组织与 platform-design.md 的站点地图存在结构性偏差,属一次性重构决策。
2. **KG ↔ 材料数据的关联与交互断裂**(UAT-3/5):Cytoscape 交互层在两个图谱页面(/ontology 已修、/kg/explore 未修)表现不一致;KG 节点与 materials 表的 id 体系未打通("Material not found")。G2(材料问答)与图谱浏览的可用性被同一族问题压制。
3. **抽取产物的展示语义错位**(UAT-4):文献页展示「图谱关系」,而材料数据库需要「属性 + 具体值 + 置信度 + 原文回链」。抽取管线本体(本体驱动、置信度、chunk 溯源)均已存在,缺的是**落库语义对齐(属性而非关系节点)与展示层组装**——这是 G1 抽取价值的最终呈现,建议作为独立 EPIC 立项而非散点修复。
4. **语义检索的可用性定位**(UAT-6):登录墙(产品决策)×索引覆盖(BUG-04)双重限制,使 G2 目标在公开站点上事实不可用;需产品层面对「匿名可用性」与「登录后质量」分别拍板。
